# Reporting integrity and security issues

If a bug could select the wrong device, bypass model/image checks, leak private data, or write outside the intended component, provide a minimal reproducible description and the relevant source location. Don't attach credentials, raw backups, device serials, or private logs.

Use GitHub's private vulnerability reporting if it is enabled for this repository. Otherwise open a minimal issue asking for a private reporting route, without posting sensitive exploit details. No private-reporting channel is claimed unless the repository owner has actually enabled one.

The maintainer can reproduce software issues through offline tests. Real hardware testing and recovery behavior must be documented separately.
